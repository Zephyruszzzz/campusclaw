# 问题一：文件上传逻辑？支持哪种文件类型？txt、md 以外文件是否支持？

> 适用代码版本：当前工作区 `campusClaw`（Flask + SQLite + 私有上传目录）。
> 结论均以源码为准，括号内为 `文件:行号`。

---

## 1. 结论速览

| 问题 | 答案 |
| --- | --- |
| 支持的类型 | **只有 `.txt` 和 `.md`**（`config.py:24`，`ALLOWED_EXTENSIONS = ("txt", "md")`） |
| txt / md 以外的文件 | **不支持，直接拒绝**，返回 `415 UNSUPPORTED_FILE_TYPE` |
| 内容编码 | 必须能被**严格 UTF-8 解码**（允许 BOM，拒绝含 `\x00`、拒绝纯空白） |
| 单文件大小 | ≤ **10 MiB**（`config.py:19`），超出返回 `413` |
| 请求体总量 | ≤ **11 MiB**（`config.py:20`，Flask `MAX_CONTENT_LENGTH`），超出由框架返回 `413` |
| 每请求文件数 | **恰好 1 个**，0 个或多个都报 `400 INVALID_FILE` |
| 谁能上传 | **只有教师**（`role == "teacher"`），学生返回 `403 ROLE_FORBIDDEN` |

**一句话：只收单个 UTF-8 的 `.txt` / `.md`，其余类型一律 `415`。**

---

## 2. 接口定义

```
POST /api/materials/upload        （Content-Type: multipart/form-data）
```

请求字段（白名单，`materials.py:26`）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 文件段，表单字段名固定为 `file`（`materials.py:27`） |
| `title` | 否 | 标题；省略时用「文件名去掉扩展名」推导 |
| `csrf_token` | 是 | 也可通过 `X-CSRF-Token` 请求头提交（`request_context.py:88-89`） |

- 成功返回：`201 {"material_id": <int>, "status": "active"}`（`material_views.py:105`）
- 失败返回：统一结构 `{"error":{"code":"...","message":"..."}}`（`errors.py:25-26`）

---

## 3. 判定顺序（先权限、后内容）

入口在 `material_views.py:77-105`，鉴权链在 `request_context.py:100-106`：

1. **认证**：无有效会话 → `401 AUTH_REQUIRED`
2. **角色**：非教师 → `403 ROLE_FORBIDDEN`（角色判定优先于资源是否存在）
3. **CSRF**：令牌不符 → `403 CSRF_INVALID`（失败不产生任何写入副作用）
4. **身份字段拦截**：表单出现 `class_id / role / user_id / uploaded_by` → `400 IDENTITY_FIELD_FORBIDDEN`
   （班级、上传者一律取服务端会话，客户端传什么都不采信）
5. **未知字段**：出现白名单外字段 → `400 INVALID_FIELDS`
6. **文件数量**：`request.files` 除 `file` 外还有别的键，或 `file` 不止 1 个 → `400 INVALID_FILE`

---

## 4. 内容校验链（业务层 `materials.py:138-224`）

按顺序执行，任一步失败即中止，**不落库、不留文件**：

| 步骤 | 检查 | 失败结果 |
| --- | --- | --- |
| 1 | `sanitize_filename()`（`:94-100`）只取 basename，剥目录段、`\x00`、非可打印字符 | 结果为空 → `400 INVALID_FILE` |
| 2 | 文件非空 | 0 字节 → `400 INVALID_FILE` |
| 3 | 大小 ≤ `max_file_bytes`（10 MiB） | 超出 → `413 FILE_TOO_LARGE` |
| 4 | `detect_extension()`（`:103-110`）小写扩展名须在 `("txt","md")` 内 | 否则 → **`415 UNSUPPORTED_FILE_TYPE`** |
| 5 | `decode_text()`（`:119-131`）严格 UTF-8 解码 | 解码失败 / 含 `\x00` / 去空白为空 → `422 PARSE_FAILED` |
| 6 | `validate_title()`（`:84-91`）标题 1～200 个 Unicode 码点、无控制字符 | 否则 → `400 INVALID_TITLE` |

---

## 5. 落盘方式（两阶段 + 同卷移动）

```
暂存写盘  →  双表同事务 INSERT  →  同卷 os.replace 移动  →  COMMIT  →  返回 id
```

- 存储键为随机 `uuid4().hex.<ext>`（`storage.py:37`），**原文件名不参与路径**，杜绝路径穿越与文件名猜测
- 暂存目录：`uploads/.staging/`；最终路径：`uploads/<class_id>/<storage_key>`（`storage.py:45`）
- 事务范围：`materials` 表 + `knowledge_entries`（正文文本）表（`materials.py:184-198`）
- 任一步失败：`ROLLBACK` + 删除暂存/已移动文件（`materials.py:219-224`），保证「要么全成，要么不留痕」

---

## 6. 为什么 txt / md 以外不支持

项目定位是「纯文本材料的班级共享」，README 明确把 **PDF / Word / 图片 / 压缩包解析**列入「不做」清单。
后端既没有对应解析器，扩展名白名单也只开放 `txt` / `md`，因此上传 `.pdf`、`.docx`、`.png`、`.zip`
会在第 4 步被 `415` 挡下，**文件内容根本不会被读取**。

> 补充：前端 `<input type="file" accept=".txt,.md">`（`materials.html:20`）只是**浏览器侧**的友好过滤。
> 真正的强制校验在后端；即使绕过前端、把 `.pdf` 改名成 `.txt`，也会在第 5 步因 UTF-8 解码失败被 `422` 拒绝。
