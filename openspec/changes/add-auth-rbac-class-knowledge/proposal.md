# CampusClaw 身份、权限、班级隔离与材料入库变更提案

版本：1.0　日期：2026-09-18　变更标识：`add-auth-rbac-class-knowledge`

状态：需求规约交付，尚未实现或完成业务验收。

## Why

教学材料分散在群文件与网盘中，学生缺少统一查看入口，班级之间也缺少明确的数据访问边界。本变更为 CampusClaw 建立可登录、可授权、按班级隔离的材料管理基础：教师上传教学材料，系统保存文件并解析入库，本班教师和学生可以读取；学生不能修改材料，其他班级不能访问。

验收必须能回答：谁可以操作、操作哪个班级的数据、成功后数据库和文件如何变化、失败后保留什么、用什么证据判定。

## What Changes

- 教师、学生通过预置账号密码登录，建立可撤销会话；未登录页面跳转登录页，受保护 API 返回 401；支持退出登录。
- 服务端根据用户身份执行角色授权：教师可上传、读取、修改标题和删除本班材料，学生仅可读取本班材料。
- 材料与知识内容以班级为访问边界，列表查询和按 ID 操作均在服务端过滤；客户端不能指定或覆盖自身角色、用户或班级。
- 上传 `.txt`、`.md` 后完成文件保存、UTF-8 文本解析、材料与知识库记录关联写入；本班列表从数据库读取，刷新后可见新记录。
- 教师可修改本班材料标题，不能通过此操作替换正文；教师可删除材料，并移除关联知识内容和原文件，清理异常可恢复。
- 预置 A/B 两班、教师 A、学生 A1/B1及可区分的样本材料；建立班级、用户、讲义、作业、助手、技能六类核心实体。
- 密码使用 bcrypt 哈希，签名密钥通过服务端环境变量注入；标准启动方式为 Docker Compose，提供匿名 `GET /health`，数据库和上传目录持久化。
- 本次产出仅为本目录的四份 Markdown。业务代码、Docker 配置、初始化脚本、README 更新均属于后续 Apply 任务。

- `auth-upload`：登录与会话撤销、教师/学生授权、服务端班级隔离、材料上传及知识入库、标题修改与删除、初始化数据、安全配置和部署验收。完整要求见 [spec.md](specs/auth-upload/spec.md)。

### Modified Capabilities

无。本交付目录尚无既有主规格，不宣称已修改任何运行中的系统。

## Non-goals

- 不做注册、找回密码、改密页面、验证码、OAuth/OIDC 或 SSO。
- 不做管理员角色、多校多租户、一个用户加入多个班级或教师跨班代操作。
- 不做 PDF、Word、图片、压缩包解析，不做 OCR、文件批量上传、断点续传和版本覆盖。
- 不做向量化、全文搜索、RAG 检索、AI 问答、对话助手、Agent 编排、技能开关或 MCP 运行时；“入库”在本变更中指可关联查询的解析全文持久化。
- 不做作业布置、提交、批改、成绩、错题本及业务审计平台；作业、助手、技能仅建表预留。
- 不做材料正文编辑、回收站恢复、跨班分享、公开文件链接；修改范围仅为标题。
- 不做 Kubernetes、多副本高可用或完整 CI/CD；Docker Compose 面向课程本地/演示环境。
- 不将前端隐藏按钮当作授权或隔离措施；不将模型声称完成、截图里出现按钮或仅返回成功提示作为验收通过依据。
